1. Que produisent vos macros ?

Dans config_macros.h, XZONE génère un littéral struct :

c

  .regs[PC] = pc,

  .pmpaddr  = { … }

devient au final dans un initializer

Le cœur du problème, c’est que vos macros XZONE/ZONE_n génèrent des initialiseurs de struct qui s’attendent à des tableaux intégrés (regs[32], pmpcfg[2], pmpaddr[8], excpt_handlers[N_EXCEPTIONS]), alors que dans BarocqMZ vous avez déclaré des pointeurs à la place :

c
// TinyMZ
typedef struct zone {
    uintptr_t       regs[32];
    uint32_t        pmpcfg[2];
    uintptr_t       pmpaddr[8];
    uintptr_t       excpt_handlers[N_EXCEPTIONS];
    …
} zone_t;

// BarocqMZ
struct Br_interface_zone {
    unsigned long long *regs;       // ← incompatible
    unsigned int         *pmpcfg;   // ← incompatible
    unsigned long long *pmpaddr;    // ← incompatible
    unsigned long long *excpt_handlers; // ← incompatible
    …
};

Du coup votre initializer

c
struct Br_interface_zone zones[N_ZONES] = ZONE_CONFIG;

essaie de faire

c
{ .regs[PC] = pc, … }

or regs n’est pas un tableau, c’est un pointeur ; vous ne pouvez donc pas l’initialiser par désignateur de champ comme un array.

Deux solutions possibles

  1. Revenir au même layout que TinyMZ
    Dans br_interface.h (ou dans le template de génération), redéclarez Br_interface_zone avec des tableaux inline au lieu de pointeurs :

    c
    struct Br_interface_zone {
  unsigned long long  id;
  unsigned long long  regs[32];
  unsigned int        pmpcfg[2];
  unsigned long long  pmpaddr[8];
  unsigned long long  ustatus;
  /* … */
  unsigned long long  excpt_handlers[N_EXCEPTIONS];
};

    De même pour l’interruption :

    c
    struct Br_interface_intrp_handler {
  struct Br_interface_zone *zone;
  unsigned long long        handler;
};

    Et dans Br_interface_kernel :

    c
    struct Br_interface_kernel {
  struct Br_interface_zone         zones[N_ZONES];
  struct Br_interface_intrp_handler intrp_handlers[N_INTERRUPTS];
  /* … */
};

    Avec ça, vos macros XZONE / ZONE_n s’appliquent directement et tous les .regs[PC], .pmpcfg = { … } fonctionneront.

  2. Adapter vos macros à des pointeurs dynamiques
    Si vous tenez absolument à garder des champs pointeurs, il faudrait que vos macros n’insèrent plus d’initialiseur struct inline, mais plutôt :

    • Déclarer des arrays statiques à part (ex. static unsigned long long zone0_regs[32] = { … };)

    • Puis construire vos struct Br_interface_zone en assignant ces pointeurs :

      c
      #define XZONE(…)                                                     \
  { .regs = zone##_regs, .pmpcfg = zone##_pmpcfg, /* … */ },

    Mais c’est beaucoup plus verbeux et sujet à erreurs.

→ Recommendation

La première approche est de loin la plus simple et la moins fragile : alignez votre struct Br_interface_zone sur celle de TinyMZ, c’est‑à‑dire avec des tableaux intégrés, et ajustez Br_interface_intrp_handler et Br_interface_kernel en conséquence.             for (size_t j = 0; j < i; j++) free(br_zones[j]);
